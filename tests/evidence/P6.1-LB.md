## Incident found and fixed during the run

`stats socket ipv4@0.0.0.0:9999 ssl crt ... verify required level admin` is accepted by `haproxy -c` (3.2.26) but the `ssl` parameters are ignored: for about 10 minutes (13:50-14:00Z) the admin CLI was reachable in **plaintext** on the public IP (a `show info` from management answered). It was closed by removing the line and reloading (connection refused from outside afterwards) and replaced by `fe_admin`, a normal TCP frontend with TLS and `verify required` in front of the local socket, with a command allowlist. No `set`/`disable` command was sent to the plaintext listener by this run; the HAProxy logs for that window show no other 9999 client. Recorded in docs/08 so the line is not reintroduced.

## Other defects fixed

- Single-file bind mounts kept the old inode after Ansible replaced `haproxy.cfg`: reloads re-read stale content. The whole `haproxy/` directory is mounted instead.
- The server-state file restored a stale container address for `be_acme` (Compose reassigned IPs), so the production HTTP-01 validation got 503. `be_acme` now uses `load-server-state-from-file none`.
- `${APP_HOST}` inside `str()` is not expanded unless double-quoted.
- The admin socket directory is a bind mount owned by uid 99 (a named volume is root-owned and HAProxy could not bind).
- `lb` role decides staging versus production from the issuer of the held certificate (a failed production attempt rewrote the stored CA and made the old check skip the reissue).
- `curlimages/curl` was pulled onto the LB for a diagnostic and removed again.
