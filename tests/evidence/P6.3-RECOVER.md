## 3. scale_in every minute

Each scale_in ended `succeeded`/`noop` (`primary_outage`, later `no_candidate`), which is the designed gate result. The cause of the churn was upstream: `CdrCpuLow` stays firing, Alertmanager repeats it every 60 s (`repeat_interval`), and `ops.open_operation` coalesces only while the previous operation is non-terminal, so each finished noop was replaced by a new operation. Fix: `actions/alert_intent.py` records `skipped: primary_outage` / `skipped: no_candidate` and opens nothing in those cases (the gate still rechecks under the lock; overflow recovery with the warm standby `active` still gets its operation). Tests: `test_alert_intent_cpu_low_repeats_open_no_scale_in_while_the_primary_is_out_and_resume_after_it_resolves`, `..._no_operation_when_there_is_no_elastic_vm_and_the_warm_standby_is_not_serving`. Live: no scale_in operation created after 20:32:58Z with `CdrCpuLow` still firing.
