# Phase 4 live checks (tests/compose)

**Everything here is a local simulation, not real infrastructure.** Each script brings up a throwaway Postgres 17 container and StackStorm 3.9.0 (amd64, emulated on Apple silicon) under Docker Desktop, runs the real `cdr` pack against the simulation adapter
(`provider_adapter: simulation`: a flock'd JSON state file stands in for the provider APIs; every instance row carries `simulated=true`), and tears it down. Routing, drain and the Prometheus reload are simulated too (HAProxy and the real adapter are P5/P6).
Timings are not representative of the 2 vCPU / 4 GB management VM. Pass counts and dates of the latest runs: `PHASE4-EVIDENCE.md`. Output of each run is committed as `<script>.local.out`; failures also write evidence under `evidence/` (gitignored).

Needs docker, pnpm, node, python3, openssl. Shared bring-up: `lib-st2-local.sh`; shared operation helpers: `lib-st2-ops.sh`. Static monitoring checks: `promtool.sh` (also renders `prometheus.yml` with another `policy_version` through the pack's `prom_render.py` and validates it).

| T08 | `t08-t09-local.sh` | The provider never becomes ready on either provider (checkpoints 30/45/60 s): an `operation.waiting` event at each checkpoint, attempt 1 failed then cleaned with absence evidence, attempt 2 on the same provider, then Linode, then one `provision.exhausted` incident and a failed operation; every slot free at the end; no second exhausted loop; the capacity guard did not delay the runs. |
| T09 | `t08-t09-local.sh` | A create that times out while the VM exists (ambiguous): the attempt is `uncertain`, the slot `held_uncertain` and counted, zero further create calls (adapter call log), no fallback; reconcile with the provider answering resolves the slot with evidence. T09b: the database stops answering for 25 s while `scale_out` holds the lease: the operation ends terminal and the lease is free. |
| T10 | `t10-t22-local.sh` | `primary_failure`, `scale_out` and reconcile fired together: exactly one lease holder per fencing generation, one slot reserved per operation, adapter create count equals the intended count; T10b: an expired lease is taken over only by reconcile and the fenced worker's next call gets `lease_lost` (CDR01). Also the 60 s reconcile timer, the restart gate (runner killed mid-create: reconcile adopts by operation id, no duplicate create) and the orphan gate (a tagged resource nothing explains is held and reported, never deleted). |
| T22 | `t10-t22-local.sh` | Normal scale-in through the `cpu.low` webhook releases the newest elastic slot only after the provider confirms absence; with the primary down, `cpu.low` ends as a no-op `primary_outage` with zero `begin_slot_release` and no delete; a queued scale-in is superseded by `primary_failure`. |
| T27 | `t27-t36-local.sh` (section 4) | Warm standby repair, each classification driven by faults and the simulation producer `cdr.standby_unhealthy`: healthy (record only), (a) app broken -> one redeploy of the same VM, (b) powered off -> one power-on then one deploy, (c) absent -> release with provider-API absence evidence, reserve and provision the warm slot again (exactly one create), each ending ready + pinned digest + routing `backup` (simulated HAProxy view) + `standby.repaired`; (d) provider answer unknown -> slot `held_uncertain`, incident `standby.uncertain:warm`, ZERO creates, deploys, power-ons and deletes. |
| T36 | `t27-t36-local.sh` (section 5) | Warm provider `api_unknown`: `interim-warm-linode` reserved and bound (one create, on Linode, none on the warm provider), the held warm slot and the interim slot both counted against their providers' caps, a reservation beyond the cap refused; after the provider answers again reconcile resolves the warm slot from attempt tags, requests a repair, then the surplus interim slot is released through scale-in only with provider-API absence evidence and exactly one warm-role slot stays bound. |
| apply_policy | `t27-t36-local.sh` (section 6) | Happy path (label re-rendered and loaded, version active, no lease); failed reload keeps the old version active and restores the label; a cap lowered below the occupied count is a pending transition (nothing deleted, reservations above the cap refused, exclusive lease taken and released); an HAProxy setting fails `not_implemented` and applies nothing. |
| skeletons | `t27-t36-local.sh` (section 7) | `failback`, `start_load_test`, `stop_load_test`, `create_backup`, `verify_backup`, `restore_application` triggered directly: the operation ends `failed` with `outcome.error: not_implemented` at the first planned step; no lease, no slot change, no adapter call, no success event. |
